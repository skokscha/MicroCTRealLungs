# Анализ связности пористой среды: методы и наш прототип

Обзор по итогам встречи (В. Кудрявцев ↔ С. Кононов) + что уже реализовано
на реальных данных (воздушная фаза куба лёгкого 510×510×510, воксель 4.9 мкм).
Термины даны так, чтобы их можно было напрямую загуглить/спросить у LLM.

## 1. Постановка (по встрече)

- Среда задана сеткой ячеек: 1 = воздух (проводящая фаза), 0 = стенка.
- Связность — **только по граням** (в 2D — 4-соседство, в 3D — 6-соседство),
  диагональные соседи НЕ считаются связанными.
- Задачи:
  1. есть ли сквозной канал от стенки до противоположной (проницаемость/перколяция);
  2. найти **узкие места** («ущелья», бутылочные горлышки), через которые
     вынуждены проходить все или большинство сквозных маршрутов;
  3. (перспектива) оценка ширины каналов и пропускной способности ущелий.

## 2. Словарь методов (что советуют LLM и что есть в библиотеках)

| метод | что делает | библиотека | роль в нашей задаче |
|---|---|---|---|
| **Перколяция / компоненты связности** (`connected component labeling`) | красит связные области разными метками: всё, что недостижимо — отдельные метки | `scipy.ndimage.label` | ✓ сделано: есть ли сквозная компонента, доля запертых пор |
| **Волновой алгоритм (BFS)** — «навигатор» | волна от старта по соседям; первый достигший цели — кратчайший путь | `skimage.graph.MCP`, `scipy.ndimage.binary_dilation` | ✓ сделано: многоточечная волна от всей входной грани (аналог встречной волны из навигатора) |
| **Дейкстра / A\*** | BFS с ценами ячеек: кратчайший путь с весами (например, шириной канала) | `skimage.graph.MCP`, `networkx` | ✓ сделано (цена = 1 шаг); вариант с ценой «1/ширина» — шаг 2 |
| **Счётчик прохождений / betweenness centrality** | ячейка помнит, сколько маршрутов через неё прошло; высокая нагрузка = узкое место | своя реализация; строгая версия — `networkx.betweenness_centrality` | ✓ сделано (идея Владислава: «деревья запоминают путь»), 128 путей на ось |
| **Макс. поток / мин. разрез (max-flow / min-cut)** | строгая математика ущелий: мин. разрез = самое узкое сечение, его величина = пропускная способность | `networkx`, `igraph`, `porespy` | шаг 2: строго на подкубе; это «оценка пропускной способности» из п. 3 постановки |
| **Скелетизация (medial axis / SNOW)** | сжимает поры в граф-«скелет» с радиусами; узлы = развилки, рёбра = каналы | `skimage.morphology.skeletonize`, `porespy.networks.snow2` | шаг 3: оценка ширины каналов по радиусам скелета |
| **Мосты и точки сочленения** (`bridges`, `articulation points`) | удали мост — граф распадётся; строгое «единственное ущелье» | `networkx` | применимо к скелету (шаг 3), на сырой сетке слишком дорого |

Практическое правило: на воксельной сетке в сотни миллионов ячеек графовые
библиотеки (networkx) напрямую не работают — они на порядок медленнее
«объёмных» операций scipy/skimage. Поэтому стратегия прототипа: объёмные
алгоритмы на полном кубе + графовые на скелете/подкубе.

## 3. Что уже реализовано и проверено на наших данных

Скрипт `scripts/connectivity_paths.py` (движок волны — `skimage.graph.MCP`,
C-реализация Дейкстры; связность строго 6-соседняя, диагонали исключены):
расчёт на полном кубе 510³, ~3 мин на ось.

1. **Перколяция** (`scipy.ndimage.label`): воздушная фаза образует одну
   компоненту из 109.5 млн вокселей (99.56% воздуха), она касается всех
   6 граней куба → сквозные каналы есть по всем трём осям. Запертых карманов
   0.44% (1048 карманов < 1000 вокселей).
2. **Волна от грани до грани** (многоточечный старт — вся входная грань):

   | ось потока | стартовых вокселей | достигнуто выходной грани | кратчайший путь | средняя извилистость 128 путей |
   |---|---|---|---|---|
   | x | 204 073 | 99.0% | 510 вокс. (= ширина куба) | 1.007 |
   | y | 221 466 | 99.7% | 510 вокс. | 1.004 |
   | z | 232 872 | 99.6% | 510 вокс. | 1.004 |

   Извилистость ≈ 1.0: по каждой оси есть практически прямые сквозные каналы
   (среда открыта на 83%). 510 вокселей = теоретический минимум (шаг + оба
   конца), т.е. прямее уже некуда.
3. **Карта ущелий** (идея со встречи: «ячейка запоминает, кто через неё
   прошёл»): 128 кратчайших путей на ось, счётчик проходов на воксель
   (`connectivity_visits_{x,y,z}.npz`, визуализация
   `connectivity_gorges.png`). Результат: **максимальная нагрузка на один
   воксель — 11–14 путей из 128 (≤11%)**, вокселей, через которые идёт ≥50%
   путей, — ноль. Вывод: в приближении кратчайших путей выраженных
   одновоксельных ущелий нет — сеть многократно параллельна, маршруты
   расходятся по множеству альвеол. Это согласуется с высокой пористостью
   (83%): переток идёт шириной, а не через единственные перешейки.

   Оговорка: кратчайшие пути — не потоки. Для пропускной способности нужен
   max-flow/min-cut (шаг 2): расширяющийся поток сам «найдёт» самые широкие
   русла, и если где-то сечение мало — минимальный разрез это покажет числом
   вокселей в сечении.

## 4. Предлагаемые следующие шаги (после ревью прототипа)

1. **Строгий min-cut** на подкубе (~128³–256³): networkx max-flow;
   минимальный разрез = точное узкое место + его пропускная способность
   (сколько вокселей в сечении). Валидация эвристики со счётчиком.
2. **Скелетизация** (`snow2` из porespy или `skeletonize`): граф пор с
   радиусами → ширина каналов, поиск мостов в графе скелета.
3. **Встречная волна** (упоминание с встречи): запуск с двух граней
   навстречу — экономит время в 2 раза; на полном кубе сейчас не нужна,
   пригодится на бо́льших объёмах.

## 5. Ограничения прототипа (говорим честно)

- Кратчайшие пути — «прилипшие к стенкам» не идут (MCP не делает
  centerline); для ширины канала нужен скелет (шаг 2 выше).
- Счётчик прохождений — эвристика междустрочной центральности на 128
  путях; строгое решение — max-flow/min-cut.
- Одна фаза (воздух). Для ткани алгоритм тот же, инвертировать маску.
